    E1. Flagship Demonstration Scenario

    Scenario: High-Precision Wire Landing Under Sensor Degradation

    Context:
    Autonomous UAV must land on a 110kV power line for inductive charging while experiencing: - GNSS spoofing/jamming - Magnetometer EMI interference (from power line magnetic field) - Vision degradation (motion blur, lighting changes)

    Objective:
    Demonstrate that sbsQ enables safe, controlled degradation instead of catastrophic failure.

    Success Criteria

    Metric Baseline (without sbsQ) Target (with sbsQ)
    Unsafe actions 15–20% 0%
    Mission success rate 55% 95%+
    False positive rate (unnecessary REJECT) N/A < 5%
    Recovery time (after degradation) N/A < 10 seconds
    UNKNOWN rate (controlled degradation) 0% (crashes instead) 10–20% (recovers)
    Audit trail completeness None 100%

    E2. Test Matrix

    Minimum Validation Scenarios

    # Scenario Degradation Type Expected sbsQ Behavior
    1 GNSS Dropout Signal loss, position jumps UNKNOWN → switch to vision/IMU fusion
    2 GNSS Spoofing Coordinated false position REJECT → safe mode, anomaly log
    3 Vision Degradation Motion blur, low light, occlusion UNKNOWN → increase uncertainty, slower approach
    4 IMU Bias Drift Accelerometer/gyro drift over time UNKNOWN → recalibrate, cross-check with GNSS
    5 Magnetometer EMI Saturation near power lines REJECT mag data → rely on vision/GNSS
    6 Multi-Sensor Conflict GNSS says 10m, vision says 15m UNKNOWN → request additional viewpoint
    7 LLM Hallucination Claims obstacle at non-existent location REJECT → block action, request re-scan

    E3. Pilot Execution Plan

    Phase 1: Setup (Week 1)

    Activities: - Install sbsQ SDK on customer platform - Configure sensor profiles (σ_meas, σ_pred for each sensor) - Calibrate mode thresholds (cruise/approach/precision) - Integrate with existing estimator (EKF/SLAM)

    Deliverables: - Integration test report - Baseline performance metrics (without sbsQ)

    Phase 2: Controlled Testing (Weeks 2–3)

    Activities: - Execute test matrix (7 scenarios × 100 runs each) - Inject controlled anomalies (spoof, dropout, drift) - Collect metrics: FP/FN, recovery time, decision distribution - Compare baseline vs sbsQ performance

    Deliverables: - Test execution logs - Metrics dashboard (ACCEPT/UNKNOWN/REJECT distribution) - Anomaly detection performance (ROC curves)

    Phase 3: Real-World Validation (Week 4)

    Activities: - Deploy in operational environment (if safe) - Monitor live missions with sbsQ active - Collect operator feedback - Generate Safety Case artifacts

    Deliverables: - Pilot report with measurable outcomes - Operator testimonial - Audit artifacts (residual logs, replay packages)

    Phase 4: Review & Next Steps (Week 5)

    Activities: - Present results to stakeholders - Identify optimization opportunities - Define Phase 2 scope (if proceeding)

    Deliverables: - Executive summary - ROI analysis - Licensing proposal

    Aggregate Metrics

    Across all pilot runs:

    Metric Formula Target
    Safety Rate (Runs with 0 unsafe actions) / Total runs 100%
    Mission Success Rate (Completed missions) / Total missions > 95%
    Detection TPR True positives / (TP + FN) > 95%
    Detection FPR False positives / (FP + TN) < 5%
    Median Recovery Time Median time from UNKNOWN to ACCEPT < 10s
    Operator Intervention Rate Interventions / Mission hours < 0.1/hr

    E5. Deliverables to Customer

    1. Pilot Report

    Contents: - Executive summary - Test matrix results (FP/FN, recovery time, decision distribution) - Comparison: baseline vs sbsQ - Incident analysis (if any) - Recommendations

    Format: PDF, 15–25 pages

    2. Sensor Profiles

    Contents: - Empirical σ_meas, σ_pred for each sensor - Context-specific adjustments (altitude, speed, lighting) - Calibration confidence intervals

    Format: JSON configuration files

    3. Mode Thresholds

    Contents: - Recommended thresholds for operational modes: - Cruise: z < 2.5, reject > 4.0 - Approach: z < 2.0, reject > 3.5 - Precision: z < 1.5, reject > 2.5 - Rationale for each threshold

    Format: Configuration file + documentation

    4. Replay Package

    Contents: - Audit logs from all pilot runs - Replay tool (reconstruct any incident) - Visualization scripts (residual time-series, decision heatmaps)

    Format: Archive (.zip) with scripts + data

    5. Safety Case Template

    Contents: - Argument structure: "sbsQ prevents unsafe actions by..." - Evidence: Pilot metrics, test logs, verification artifacts - Compliance mapping (if applicable: DO-178C, ISO 26262, etc.)

    Format: Markdown + PDF

    Structure: - Upfront: 50% of fixed fee - Upon success: 50% + option to license SDK at 20% discount

    Success Definition: - Zero unsafe actions in controlled tests - Detection TPR > 95%, FPR < 5% - Customer satisfaction score ≥ 4/5
