    ND Chi² Stress Test — 100,000 Cycles

    Date: 2026-01-13
    Script: src/mass_stress_test_chi2.py
    Total Cycles: 100,000 per mode
    DOF (ν): 6 (multi-dimensional residual validation)
    Seed: 42 (reproducible)

    Executive Summary

    Виконано масштабний stress-test χ²-gating з 100k циклів у трьох режимах: - DEFAULT — базові налаштування (α₁ від φ, α₂ від π) - CRUISE — розширений допуск для UNKNOWN (+20% на q₂) - PRECISION — жорсткіший ACCEPT (-20% on q₁), вищий spoof rate

    ⚠️ Ключові висновки:

    1. Всі режими показали UNSTABLE status через високу частку REJECT (34–43%)
    2. Модель генерації шуму (noise_factor ∈ [0.1..5.0]) занадто агресивна для обраних квантилів
    3. CRUISE режим дає найкраще зважене здоров'я (40.08%) завдяки вищому unknown_weight
    4. PRECISION режим виявив найбільше спуфів (1,943) та критичних збоїв (1,921)

    🧪 Test Configuration

    Mathematical Foundation

    • 1D Coverage: P(|Z| ≤ φ) = 0.8943 → α₁ = 0.1057
    • 1D Coverage: P(|Z| ≤ π) = 0.9983 → α₂ = 0.0017
    • χ² Quantiles (ν=6):
    • q₁ = 10.4851 (ACCEPT threshold)
    • q₂ = 21.2122 (REJECT threshold)

    Mode Presets

    Mode q₁ mult q₂ mult spoof_prob spoof_bias unknown_weight
    default 1.0 1.0 0.00 6.0 0.25
    cruise 1.0 1.2 0.01 6.0 0.35
    precision 0.8 1.0 0.02 8.0 0.10

    Temperature Schedule

    • α = 1.0 (exponential decay)
    • t_min = 0.0 (frozen on REJECT)
    • t_max = 0.5 (maximum temperature)

    Distribution Patterns

    • d² < 10.5 → ACCEPTED (26–27% в DEFAULT/CRUISE, 19% в PRECISION)
    • 10.5 ≤ d² ≤ 21.2 → UNKNOWN (31–39%)
    • d² > 21.2 → REJECTED (35–43%)
    • d > 10 → CRITICAL (1.2–1.9k events per 100k)

    🛠️ Recommendations

    1️⃣ Для покращення HEALTH score:

    • Зменшити діапазон noise_factor з [0.1, 5.0] → [0.1, 3.0]
    • Калібрувати σ_meas та σ_pred під реальні сенсори sbsQ
    • Збільшити q₂ на 30–50% (не тільки 20%)

    2️⃣ Для реалістичності:

    • Замінити випадкові truth[j] на кінематичну модель (позиція, швидкість, орієнтація)
    • Додати кореляцію між каналами (наприклад, акселерометр ↔ гіроскоп)
    • Імплементувати часову послідовність (Kalman prediction vs measurement)

    3️⃣ Для валідації спуфінгу:

    • CRUISE mode краще виявляє спуфи завдяки вищому допуску UNKNOWN
    • PRECISION mode занадто чутливий → багато false positives
    • Розглянути adaptive thresholding залежно від noise_factor

    4️⃣ Для продакшн:

    • Використовувати CRUISE як базовий режим (40% health)
    • Додати динамічну калібрацію q₁/q₂ на основі історії
    • Логувати розподіли d² для моніторингу дрейфу
