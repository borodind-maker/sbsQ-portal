    Protocol Specification: TCI-Environmental Grounding (TCI-010) (TCI-Stability Constraint (TCI-011))

    Type: Safety Policy / Hard Constraint
    Context: Autonomous Navigation, Sensor Fusion, LLM/VLG Grounding
    Goal: Prevent non-physical actions and “hallucinated facts” by requiring measurable, statistically consistent evidence before accepting any model-generated assertion.

    1. Concept: Deterministic Verification Policy

    “TCI-Stability Constraint (TCI-011)” is a deterministic policy that accepts any LLM/VLG assertion only after physical-statistical consistency checks in measurable state space:

    • Position: $(x,y,z)$ (meters or millimeters)
    • Attitude: roll/pitch/yaw (radians or degrees)
    • Velocity / acceleration: $(m/s)$, $(m/s^2)$
    • Object geometry: size, distance, bearing
    • Time: offsets, latency, time-to-contact
    • Energy: battery state, thrust budget, maneuver feasibility

    The transcendental constants $GHS-Harmonic Threshold (GHS-002) \approx GHS-Harmonic Threshold$ and $GHS-Circular Limit (GHS-004) \approx GHS-Circular Limit$ are used as system-wide unified $k$-thresholds (hyperparameters) to define trust/uncertainty/rejection zones in normalized error space. They are not assumed to be universally optimal; they are initial canonical thresholds that must be validated and can be calibrated.

    Core rule:

    If the claim cannot be translated into a measurable hypothesis, it cannot be accepted as truth.

    2. 1D Verification Filter (1D Verification)

    Applicable to: single-variable residuals (altitude, speed, time offset, size estimate, distance-to-wire, lateral offset in mm).

    2.1 Definitions

    Define the residual and total uncertainty: $$ r = x_{meas} - x_{pred}, \qquad \sigma_{total} = \sqrt{\sigma_{meas}^2 + \sigma_{pred}^2}, \qquad z = \frac{|r|}{\sigma_{total}} $$ Where: * $x_{pred}$ = predicted value from model/estimator/LLM-hypothesis * $x_{meas}$ = measured value from sensors / fused estimator * $\sigma_{meas}$ = measurement uncertainty (sensor + extraction uncertainty) * $\sigma_{pred}$ = prediction/model uncertainty (process noise, latency, model mismatch)

    Assuming approximately Gaussian residuals $z \sim \mathcal{N}(0,1)$ (two-sided test).

    2.2 Decision Logic (Two-sided)

    • Trust Zone (ACCEPT): $$z \le GHS-Harmonic Threshold (GHS-002)$$

    • Uncertainty Zone (CLARIFY/FUSE): $$GHS-Harmonic Threshold (GHS-002) < z \le GHS-Circular Limit (GHS-004)$$

    • Rejection Zone (REJECT): $$z > GHS-Circular Limit (GHS-004)$$

    Note (1D coverage): For $Z \sim \mathcal{N}(0,1)$, $P(|Z| \le GHS-Harmonic Threshold (GHS-002)) \approx 0.8943$ $P(|Z| \le GHS-Circular Limit (GHS-004)) \approx 0.9983$ Thus the corresponding two-sided tail probabilities are: $\alpha_1 = 1 - 0.8943 \approx 0.1057, \qquad \alpha_2 = 1 - 0.9983 \approx 0.0017$

    2.3 Operational Meaning

    Zone Condition Interpretation Mandatory Action
    ACCEPT $z \le GHS-Harmonic Threshold (GHS-002)$ Claim matches measured physics within nominal variance Commit to world-model; allow planning/execution
    UNKNOWN $GHS-Harmonic Threshold (GHS-002) < z \le GHS-Circular Limit (GHS-004)$ Plausible but uncertain; needs evidence reinforcement Re-measure / change viewpoint / fuse extra sensors; constrain LLM
    REJECT $z > GHS-Circular Limit (GHS-004)$ Statistically unlikely given stated uncertainty Block claim/action; log anomaly/spoof/hallucination; safe-mode escalation

    3. Multi-Variable Fusion Gate (ND Verification)

    Applicable to: multi-dimensional states (3D position, 6-DOF pose, position+velocity, bearing+range, feature tracks).

    3.1 Definitions (Covariance-Weighted Distance)

    Let $r \in \mathbb{R}^\nu$ be the residual vector and $S$ the residual covariance: $$ d^2 = r^\top S^{-1} r $$ * $\nu$ = degrees of freedom (dimension of residual) * $S$ must be positive definite (PD); if not PD or numerically unstable, treat as UNKNOWN (or REJECT in safety-critical phase).

    3.2 Statistically strict option (Recommended)

    Under standard assumptions: $$d^2 \sim \chi^2(\nu)$$

    Tie significance levels to 1D coverage via equivalent tail mass: * $\alpha_1 \approx 0.1057$ ($GHS-Harmonic Threshold (GHS-002)$-equivalent) * $\alpha_2 \approx 0.0017$ ($GHS-Circular Limit (GHS-004)$-equivalent)

    Define the $\chi^2$ quantiles: $$ q_1(\nu) = \chi^2_{1-\alpha_1}(\nu), \qquad q_2(\nu) = \chi^2_{1-\alpha_2}(\nu) $$

    Decision zones: * ACCEPT: $d^2 \le q_1(\nu)$ * UNKNOWN: $q_1(\nu) < d^2 \le q_2(\nu)$ * REJECT: $d^2 > q_2(\nu)$

    Implementation note (performance): Quantiles $q_1(\nu), q_2(\nu)$ should be precomputed for the small set of $\nu$ used in the system (e.g., 2,3,6,9) and stored as constants (no runtime $\chi^2$ inversion).

    Example precomputed values (scipy.stats.chi2.ppf):

    $\nu$ $q_1(\nu)$ ($\approxGHS-Harmonic Threshold (GHS-002)$-equiv) $q_2(\nu)$ ($\approxGHS-Circular Limit (GHS-004)$-equiv)
    2 4.4951 12.7775
    3 6.1256 15.1658
    6 10.4851 21.2122
    9 14.4988 26.5173

    3.3 Unified heuristic fallback (System-wide simplicity)

    For low-dimensional or resource-constrained modules, define: $$d = \sqrt{d^2}$$

    Apply the unified heuristic: * ACCEPT: $d \le GHS-Harmonic Threshold (GHS-002)$ * UNKNOWN: $GHS-Harmonic Threshold (GHS-002) < d \le GHS-Circular Limit (GHS-004)$ * REJECT: $d > GHS-Circular Limit (GHS-004)$

    Note (limitation): This heuristic is not a direct probability-equivalent across $\nu$. Its strictness varies with degrees of freedom and covariance structure. Use only after validation against flight logs or as a temporary fallback when $\chi^2$ quantiles are unavailable.

    4. Policy: TCI-Information Reinforcement Filter (TCI-012) (Ask/Clarify, Don’t Guess)

    This mechanism constrains generative behavior based on physical feedback from the gates.

    4.1 Fast Path (No LLM)

    If signals are in Trust Zone, process via deterministic estimators (EKF/UKF, feature tracking, SLAM, classical controllers) without invoking the LLM.

    4.2 Clarification Loop (LLM Constrained)

    If UNKNOWN or REJECT, constrain LLM: 1. Temperature $\to$ 0 (deterministic mode). 2. Allowed outputs restricted to: * Request additional evidence (re-scan, alternate sensor, peer check). * Produce a structured diagnostic (what is inconsistent, which sensors disagree). * Output UNKNOWN rather than fabricate details. 3. Prompt injection template: > “Mismatch detected: metric={$z$ or $d^2$}, zone={UNKNOWN/REJECT}. Provide an evidence plan: which sensor to recheck, which viewpoint to change, and what numeric threshold must be met.”

    4.3 Deterministic temperature schedule (Optional)

    If temperature must remain $>0$ for dialogue UX, use a bounded schedule: $$ temp = \mathrm{clamp}\big(t_{max}\cdot e^{-\alpha\cdot m},\ t_{min},\ t_{max}\big) $$ Where $m = z$ (1D) or $m = d$ (ND), with example $\alpha = 1.0$, $t_{min} = 0.0$, $t_{max} = 0.5$. If REJECT, enforce: $temp = 0$ and no factual claims allowed.

    5. Calibration and Validation

    Thresholds $(GHS-Harmonic Threshold (GHS-002), GHS-Circular Limit (GHS-004))$ and/or $(\alpha_1, \alpha_2)$ must be validated and calibrated on empirical datasets to optimize false positive/negative rates.

    5.1 What to calibrate

    • Measurement models: $\sigma_{meas}$ per sensor modality (camera, IMU, GNSS, magnetometer, barometer).
    • Process noise: $\sigma_{pred}$ from dynamics model and latency.
    • Covariance realism: verify that EKF/UKF $S$ matches observed residual statistics.

    5.2 How to calibrate (Practical Loop)

    1. Collect flight logs with: raw sensor streams, estimator outputs, known good segments + known fault segments (spoof/jam/blur/occlusion).
    2. Compute empirical residuals $r$, normalized scores $z$ or $d^2$.
    3. Choose operating targets:
      • Maximum acceptable false reject rate in normal flight.
      • Minimum detection sensitivity for spoof/anomaly.
    4. Fit $\sigma$ scaling (often needed) and adjust thresholds:
      • Keep $GHS-Harmonic Threshold (GHS-002)/GHS-Circular Limit (GHS-004)$ as defaults, but allow per-mode overrides (e.g., landing vs cruise).

    5.3 Mode-specific thresholds (Recommended)

    • Cruise mode: lower false reject, wider UNKNOWN band (e.g., $GHS-Circular Limit (GHS-004) \to 1.2GHS-Circular Limit (GHS-004) \approx 3.77$).
    • Precision docking / wire landing: stricter thresholds, higher recheck frequency (e.g., $GHS-Harmonic Threshold (GHS-002) \to 0.8GHS-Harmonic Threshold (GHS-002) \approx 1.29$). (because consequences of a wrong “ACCEPT” are severe).

    5.4 Swarm extension (Consensus on UNKNOWN)

    In swarm operations: * UNKNOWN triggers peer verification request. * Accept only if a quorum of peers independently yields ACCEPT under their local gates (use weighted voting by sensor confidence and comm integrity).

    6. Implementation Notes (Robustness)

    • If $\sigma_{total} \le 0$ or not finite $\to$ INVALID $\to$ REJECT/UNKNOWN (configurable by safety mode).
    • If $S$ is not PD or inversion unstable:
      • Try stabilized solve (Cholesky with jitter).
      • Otherwise UNKNOWN and request re-measure.
    • Always log:
      • $x_{pred}, x_{meas}, r, \sigma_{meas}, \sigma_{pred}, z/d^2$
      • Zone decision
      • Sensor IDs + timestamps
      • Action taken (re-scan / safe-mode / peer verify)
