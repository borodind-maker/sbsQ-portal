    Coding Standards for SmartBees Project

    Version: 1.0
    Date: 2026-01-25
    Status: MANDATORY

    Language and Encoding Rules

    Rule 1: Code Files - English Only

    ALL code files MUST use English exclusively: - Python files (.py) - C++ files (.cpp, .h, .hpp) - JavaScript/TypeScript files (.js, .ts) - Lua files (.lua) - Any other programming language files

    Includes: - Docstrings - Comments - Variable names - Function names - Class names - Module names - Error messages - Log messages

    Rationale: 1. Avoids Unicode encoding issues on Windows (cp1252) 2. International collaboration (team members worldwide) 3. Standard practice in open-source projects 4. Better compatibility with tools and IDEs 5. Easier code reviews and maintenance

    Rule 2: Documentation Files - Any Language Allowed

    Documentation files CAN use ANY language: - Markdown files (.md) - Text files (.txt) - README files - Design documents - User guides

    File naming: - Use descriptive English names - Add language suffix if not English: README.md, README_UA.md

    Allowed in documentation: - Unicode characters (Cyrillic, Chinese, etc.) - Emoji - Special symbols - Multiple languages

    Examples

    Python File Example (CORRECT)

    """
Swarm Formation Module
=====================
Provides geometric formations for drone swarms.

Author: sbsQ Team
"""

import math
from typing import Tuple

PHI = (1 + math.sqrt(5)) / 2  # Golden ratio


def fibonacci_sphere(index: int, total: int, radius: float) -> Tuple[float, float, float]:
    """
    Calculate position on Fibonacci sphere.

    Uses golden angle for even distribution.
    """
    # Calculate spherical coordinates
    phi = math.acos(1 - 2 * (index + 0.5) / total)
    theta = PHI * index

    # Convert to Cartesian
    x = radius * math.sin(phi) * math.cos(theta)
    y = radius * math.sin(phi) * math.sin(theta)
    z = radius * math.cos(phi)

    return (x, y, z)

    Exception Handling

    When non-English is REQUIRED

    If you absolutely need non-English text in code (e.g., displaying to users):

    # Store strings in external config/i18n files
MESSAGES_EN = {
    "error_connection": "Connection failed"
}

MESSAGES_UA = {
    "error_connection": "З'єднання не вдалося"  # OK - in data file
}

# In code - still English
def get_error_message(lang: str, error_code: str) -> str:
    """Get localized error message."""
    messages = MESSAGES_EN if lang == "en" else MESSAGES_UA
    return messages.get(error_code, "Unknown error")

    Enforcement

    Pre-commit Checks

    1. Scan all .py, .cpp, .js files for non-ASCII characters
    2. Flag for review if non-English detected
    3. Allow exceptions only in:
    4. Test data strings
    5. i18n/localization files

    Code Review

    • Reviewers MUST reject PRs with non-English code
    • Exception: Legacy code being migrated (with plan)

    Migration Plan for Existing Code

    Phase 1 (Immediate)

    • All NEW code: English only
    • Fix files causing Unicode errors

    Phase 2 (Ongoing)

    • Gradual refactoring of existing Ukrainian code
    • Priority: Core modules (nature_math, formations)

    Phase 3 (Future)

    • Full English codebase
    • Ukrainian docs maintained separately
